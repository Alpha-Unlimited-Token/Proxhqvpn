  QUICK INSTALL — ONE COMMAND
══════════════════════════════════════════════════════════════════════════════

  The fastest way to install GhostNet. Copy and paste one line.

  LINUX & MACOS
  ─────────────
  Open Terminal and run:

    curl -fsSL https://get.ghostnet.app | bash

  That's it. GhostNet downloads, installs, and opens in your browser.

  OPTIONS (add after the command):
    Different folder:       | bash -s -- --dir ~/apps/ghostnet
    Different port:         | bash -s -- --port 8080
    Install as service:     | bash -s -- --service
    Folder + port + service:| bash -s -- --dir ~/ghostnet --port 8080 --service

  WINDOWS
  ───────
  Open PowerShell as Administrator and run:

    irm https://get.ghostnet.app/win | iex

  GhostNet downloads, extracts to C:\GhostNet, creates a desktop shortcut,
  and opens in your browser automatically.

  OPTIONS (add before the pipe):
    $env:GHOSTNET_PORT="8080"; irm https://get.ghostnet.app/win | iex

  ─────────────────────────────────────────────────────────────────────────
  IF YOU ALREADY DOWNLOADED THE ZIP — use the easy setup scripts inside:
    Linux/macOS:  bash ghostnet-setup.sh    (in the extracted folder)
    Windows:      Double-click ghostnet-setup.bat   (in the extracted folder)
  ─────────────────────────────────────────────────────────────────────────

  NOTE ON THE VPN DAEMON
  GhostNet's management dashboard (the full web interface) requires no
  additional software — it runs from the package above.
  The VPN routing daemon (actual traffic tunnelling) additionally needs:
    Linux/macOS: Python 3.9+, root access, and the TUN kernel module
    Windows:     WinTun driver (ghostd.py will guide you through this)
  Non-technical users can use all dashboard features without the daemon.
  See Section 5 (Linux) or Section 2 (Windows) for daemon setup.

  2. WINDOWS INSTALLATION
══════════════════════════════════════════════════════════════════════════════

  REQUIREMENTS
  • Windows 10 (version 1903 or later) or Windows 11
  • 64-bit processor
  • 200 MB free disk space
  • No additional software required — GhostNet bundles its own runtime

  STEPS

  1. Download GhostNet-Windows-x64.zip

  2. Extract the zip
     Right-click the file -> "Extract All" -> choose a folder such as
     C:\GhostNet -> click Extract.

     IMPORTANT: Do not run GhostNet from inside the zip file.
     You must extract it first.

  3. Launch GhostNet
     Open the extracted folder and double-click start.bat.
     A command-prompt window will appear and display:

       GhostNet VPN Orchestration Platform | Standalone Edition
       Server running at http://localhost:7474

  4. Open the interface
     Your default browser should open automatically. If not, open any
     browser and navigate to: http://localhost:7474

  5. Windows Defender / SmartScreen (first run only)
     Windows may show a blue "Windows protected your PC" dialog. This
     appears because the executable is not code-signed.
       -> Click "More info"
       -> Click "Run anyway"
     This is a one-time prompt. GhostNet does not connect to the internet
     on its own; all data stays on your computer.

  6. Windows Firewall prompt (optional)
     If Windows asks whether to allow GhostNet on the network, choose
     "Private networks" only. GhostNet only listens on localhost
     (127.0.0.1) — there is no need to allow public network access.

  STOPPING GHOSTNET
  Close the command-prompt window, or press Ctrl + C inside it.

  RUNNING AT STARTUP (OPTIONAL)
  Press Win + R, type shell:startup, press Enter.
  Copy a shortcut to start.bat into that folder.

  3. MACOS — APPLE SILICON (M1 / M2 / M3 / M4)
══════════════════════════════════════════════════════════════════════════════

  REQUIREMENTS
  • macOS 12 Monterey or later (macOS 13+ recommended)
  • Apple Silicon chip (M1, M2, M3, or M4)
  • 200 MB free disk space
  • No additional software required

  STEPS

  1. Download GhostNet-macOS-arm64.zip

  2. Extract the zip
     Double-click the file in Finder. macOS will extract it to the
     same folder automatically.

  3. Move to Applications (recommended)
     Drag the extracted GhostNet-macOS-arm64 folder to your Applications
     folder, or leave it anywhere you find convenient.

  4. Remove the macOS quarantine flag (required for first run)
     macOS marks downloaded files as quarantined. Open Terminal
     (Spotlight -> search "Terminal") and run:

       xattr -cr ~/Downloads/GhostNet-macOS-arm64

     Replace the path if you moved the folder elsewhere.

  5. Make the launcher executable
     In the same Terminal window:

       chmod +x ~/Downloads/GhostNet-macOS-arm64/start.sh
       chmod +x ~/Downloads/GhostNet-macOS-arm64/GhostNet

  6. Launch GhostNet

       cd ~/Downloads/GhostNet-macOS-arm64
       ./start.sh

  7. Open the interface
     Navigate to http://localhost:7474 in any browser.

  GATEKEEPER WARNING (alternative path)
  If macOS blocks the app with "cannot be opened because the developer
  cannot be verified":
    -> Go to System Settings -> Privacy & Security
    -> Scroll down and click "Allow Anyway" next to the GhostNet entry.

  STOPPING GHOSTNET
  Press Ctrl + C in the Terminal window where GhostNet is running.

  5. LINUX (x64)
══════════════════════════════════════════════════════════════════════════════

  REQUIREMENTS
  • Any 64-bit Linux distribution
    (Ubuntu 20.04+, Debian 11+, Fedora 35+, Arch, etc.)
  • glibc 2.17 or later — all modern distros qualify
  • 200 MB free disk space
  • No additional software required

  STEPS

  1. Download GhostNet-Linux-x64.zip

  2. Extract the zip:

       cd ~/Downloads
       unzip GhostNet-Linux-x64.zip -d GhostNet

  3. Make the launcher and executable runnable:

       cd GhostNet
       chmod +x start.sh GhostNet

  4. Launch GhostNet:

       ./start.sh

     You will see:
       GhostNet VPN Orchestration Platform | Standalone Edition
       Server running at http://localhost:7474

  5. Open http://localhost:7474 in any browser.

  RUNNING AS A SYSTEMD SERVICE (optional — for background operation)

  Create a service file:

    sudo nano /etc/systemd/system/ghostnet.service

  Paste the following (replace YOUR_USERNAME and the path as needed):

    [Unit]
    Description=GhostNet VPN Platform
    After=network.target

    [Service]
    Type=simple
    User=YOUR_USERNAME
    WorkingDirectory=/home/YOUR_USERNAME/GhostNet
    ExecStart=/home/YOUR_USERNAME/GhostNet/GhostNet
    Restart=on-failure
    RestartSec=5
    Environment=PORT=7474

    [Install]
    WantedBy=multi-user.target

  Enable and start:

    sudo systemctl daemon-reload
    sudo systemctl enable ghostnet
    sudo systemctl start ghostnet

  Check status:      sudo systemctl status ghostnet
  View logs:         journalctl -u ghostnet -f
  Stop the service:  sudo systemctl stop ghostnet

  STOPPING GHOSTNET (terminal mode)
  Press Ctrl + C in the window where GhostNet is running.

  8. CONFIGURATION OPTIONS
══════════════════════════════════════════════════════════════════════════════

  All configuration is done via environment variables set before launching.
  No config files need to be edited.

  CUSTOM PORT (default is 7474)
  ─────────────────────────────
  Windows Command Prompt:
    set PORT=8080 && GhostNet.exe

  Windows PowerShell:
    $env:PORT=8080; .\GhostNet.exe

  macOS / Linux:
    PORT=8080 ./GhostNet

  CUSTOM DATA DIRECTORY
  ──────────────────────
  By default all data is stored in a data/ folder next to the executable.

  macOS / Linux:
    GHOSTNET_DATA=/var/lib/ghostnet ./GhostNet

  Windows:
    set GHOSTNET_DATA=D:\GhostNetData && GhostNet.exe

  API KEY AUTHENTICATION (recommended if not on localhost)
  ─────────────────────────────────────────────────────────
  Set the API_KEY environment variable to require a bearer token:

  macOS / Linux:
    API_KEY=your-secret-key ./GhostNet

  Windows:
    set API_KEY=your-secret-key && GhostNet.exe

  Then include this header in all API requests:
    Authorization: Bearer your-secret-key

  10. DATA STORAGE & BACKUP
══════════════════════════════════════════════════════════════════════════════

  All GhostNet data lives in the data/ folder inside your installation
  directory (or the path set by GHOSTNET_DATA).

    data/
    └── ghostnet.db    <- SQLite database — nodes, rules, config, audit logs

  BACKUP
  Copy data/ghostnet.db to a safe location. That single file contains
  everything you need.

  RESTORE
  Stop GhostNet, replace data/ghostnet.db with your backup, restart.

  RESET TO FACTORY DEFAULTS
  Stop GhostNet, delete data/ghostnet.db, restart. GhostNet will
  automatically re-seed all 60 nodes on next startup.

  11. SECURITY NOTES
══════════════════════════════════════════════════════════════════════════════

  • LOCAL ONLY BY DEFAULT
    GhostNet binds to 127.0.0.1 (localhost). It is not reachable from
    other machines unless you deliberately change this.

  • DO NOT EXPOSE PORT 7474 TO THE INTERNET
    Without API key authentication and a TLS reverse proxy (nginx or
    Caddy), the management interface would be unprotected. For local use
    only, the default configuration is fine.

  • TERMINAL GHOST MODE
    When Ghost Mode is enabled, the terminal can run any outbound command.
    All Ghost Mode commands are automatically recorded in the Audit Log.
    Use Ghost Mode only in trusted environments.

  • EXTERNAL SQL CONNECTIONS
    When you connect to an external PostgreSQL server, the connection
    string is masked in the UI (password replaced with ****). Connections
    are held in memory only and are not written to disk.

  • RATE LIMITING IS ACTIVE
    500 requests/min global, 30/min terminal, 60/min SQL,
    100/min write operations.

  • WIREGUARD PRIVATE KEYS
    Stored in the local SQLite database. Treat ghostnet.db as a sensitive
    file and do not share it.

  12. TROUBLESHOOTING
══════════════════════════════════════════════════════════════════════════════

  "Port 7474 is already in use"
    Another process is using that port. Stop it, or launch GhostNet on a
    different port:
      PORT=7575 ./GhostNet   (macOS/Linux)
      set PORT=7575 && GhostNet.exe   (Windows)

  Browser shows "This site can't be reached"
    • Make sure the GhostNet window is still open and shows "Server running"
    • Try http://127.0.0.1:7474 instead of localhost (IPv6 conflict workaround)
    • Make sure your browser is not adding https:// — GhostNet is plain HTTP

  Windows: "Windows protected your PC" blocks the app
    Click "More info" -> "Run anyway". One-time SmartScreen prompt.

  macOS: "GhostNet cannot be opened because the developer cannot be verified"
    Run in Terminal:
      xattr -cr /path/to/GhostNet-macOS-arm64
    Or go to System Settings -> Privacy & Security -> Allow Anyway.

  Linux: "Permission denied" when running ./GhostNet
    Run:  chmod +x GhostNet start.sh

  Linux: Missing libc or GLIBC version error
    Your distro is too old (glibc < 2.17). Use the Universal package with
    Node.js 20+ instead.

  Dashboard shows no nodes
    The database is fresh or was reset. Go to Node Manager and click
    "Initialize Swarm" to seed all 60 nodes.

  External SQL connection fails
    • Verify host, port, username, password, and database name.
    • Ensure the PostgreSQL server allows remote connections
      (check pg_hba.conf and listen_addresses in postgresql.conf).
    • Check your firewall allows outbound connections to that host/port.

  Terminal commands not working
    • By default, only a safe allowlist of commands is permitted.
    • For full access, enable Ghost Mode via the toggle in the top-right
      of the Terminal page.
    • All commands in Ghost Mode are logged to the Audit Log tab.

  13. VPN COEXISTENCE SETUP
══════════════════════════════════════════════════════════════════════════════

  GhostNet can run alongside NordVPN, ExpressVPN, ProtonVPN, Mullvad,
  Surfshark, or any WireGuard/OpenVPN-based VPN at the same time without
  conflicts.

  The VPN Coexistence page (Tunnel → VPN Coexist in the sidebar) handles
  detection, exception rules, MTU calculation, and script generation.

  For a complete walkthrough, see Section E7 of the User Guide.
  Below is the quick-start for each platform.

  ──────────────────────────────────────────────────────────────────────────
  LINUX — FWMARK POLICY ROUTING (Recommended)
  ──────────────────────────────────────────────────────────────────────────

  Requirements: Linux kernel 3.x+, iproute2, iptables, root access.

  Quick steps:
  1. Start GhostNet and your commercial VPN.
  2. Open http://localhost:7474 → Tunnel → VPN Coexist.
  3. Select your VPN profile (NordVPN, ProtonVPN, etc.).
  4. Set "Native VPN Interface" to your VPN's interface (nordlynx, tun0, etc.).
  5. Choose mode: "fwmark Routing" (default, recommended).
  6. Click GENERATE COEXISTENCE SCRIPTS → download the Enable script.
  7. Run: sudo ./ghostnet-coexist-enable.sh
  8. Verify: ip rule list | grep fwmark

  To disable:
    sudo ./ghostnet-coexist-disable.sh

  Verify both VPNs are independently active:
    ip route show table 200       <- GhostNet routing table
    ip route show table main      <- Native VPN routing table

  ──────────────────────────────────────────────────────────────────────────
  LINUX — DOUBLE-HOP (Maximum Anonymity)
  ──────────────────────────────────────────────────────────────────────────

  Double-hop routes your traffic through GhostNet first, then through the
  native VPN as the outer tunnel. Neither your ISP nor the VPN provider
  can see your application traffic.

  1. In VPN Coexist, select mode: "Double-Hop".
  2. Run the MTU Optimizer with hop count 2 → apply result to ghostnet0:
       ip link set ghostnet0 mtu 1380
  3. Generate and run the Enable script as root.

  NOTE: Double-hop slightly reduces speed due to double encryption.
  If you notice large file transfers stalling, recheck MTU.

  ──────────────────────────────────────────────────────────────────────────
  LINUX — NETWORK NAMESPACE (Maximum Isolation)
  ──────────────────────────────────────────────────────────────────────────

  Runs GhostNet in a completely separate Linux network namespace.
  The native VPN and GhostNet cannot interfere with each other at all.

  1. In VPN Coexist, select mode: "Namespace Isolation".
  2. Generate and run the Enable script. It creates a "ghostnet-ns" namespace.
  3. Start ghostd.py inside the namespace:
       sudo ip netns exec ghostnet-ns python3 ghostd.py --mode server

  To run a specific application through GhostNet (namespace mode):
       sudo ip netns exec ghostnet-ns curl ifconfig.me

  ──────────────────────────────────────────────────────────────────────────
  MACOS — ROUTING TABLE
  ──────────────────────────────────────────────────────────────────────────

  Requirements: macOS 12+, sudo access.
  macOS does not support fwmark. GhostNet uses route add and interface
  metrics instead.

  1. Connect your commercial VPN (it will typically claim utun0 or utun2).
  2. Open GhostNet → Tunnel → VPN Coexist.
  3. Select your VPN profile.
  4. Set Target OS to "macOS".
  5. Generate and run the Enable script:
       chmod +x ghostnet-coexist-enable.sh
       sudo ./ghostnet-coexist-enable.sh
  6. Verify: netstat -rn | grep -E 'utun|10.99'

  ──────────────────────────────────────────────────────────────────────────
  WINDOWS — ROUTING TABLE
  ──────────────────────────────────────────────────────────────────────────

  Requirements: Windows 10/11, Administrator account.
  GhostNet uses interface metrics and static routes to separate traffic.

  1. Connect your commercial VPN.
  2. Open GhostNet → Tunnel → VPN Coexist.
  3. Select your VPN profile.
  4. Set Target OS to "Windows".
  5. Generate and download the Enable script (.bat).
  6. Right-click the .bat file → "Run as Administrator".
  7. Verify: route print | findstr "10.99"

  MTU on Windows (if needed):
    Run in an Administrator command prompt:
    netsh interface ipv4 set subinterface "GhostNet" mtu=1420 store=persistent

  ──────────────────────────────────────────────────────────────────────────
  INTERFACE NAMES REFERENCE
  ──────────────────────────────────────────────────────────────────────────

  Commercial VPN        Linux interface     macOS interface    Windows adapter
  ─────────────────────────────────────────────────────────────────────────
  NordVPN               nordlynx            utun0              NordLynx
  ExpressVPN            tun0                utun0              ExpressVPN
  ProtonVPN             proton0             utun1              ProtonVPN
  Mullvad               wg0 / wg-mullvad    utun0              Mullvad
  Surfshark             wg0 / tun0          utun2              Surfshark
  WireGuard (generic)   wg0                 utun5              WireGuard Tunnel
  OpenVPN (generic)     tun0                utun0              OpenVPN TAP

  GhostNet default:     ghostnet0           utun10             GhostNet

  ──────────────────────────────────────────────────────────────────────────
  EXCEPTION RULES QUICK-ADD
  ──────────────────────────────────────────────────────────────────────────

  GhostNet pre-loads three private-range bypass exceptions automatically:
    • 10.0.0.0/8        RFC 1918 — LAN traffic
    • 172.16.0.0/12     RFC 1918 — LAN traffic
    • 192.168.0.0/16    RFC 1918 — LAN traffic

  To add the VPN provider's server IP ranges as bypass exceptions,
  open Exception Rules → click "ADD ALL" next to your provider's name.
  This prevents GhostNet from intercepting your VPN's tunnel keepalive.

  ──────────────────────────────────────────────────────────────────────────
  COEXISTENCE TROUBLESHOOTING
  ──────────────────────────────────────────────────────────────────────────

  Both VPNs use the same interface name (e.g., both claim tun0)
    → Rename GhostNet's TUN interface by editing TUN_IFACE in ghostd.py
      to "ghostnet0". Regenerate scripts.

  After rebooting, coexistence rules are gone
    → The enable script does not persist across reboots by default.
      To persist: add the script to /etc/rc.local (Linux) or a Login Item
      (macOS) or Task Scheduler (Windows).

  DNS is leaking from one VPN to the other
    → Go to GhostNet → Leak Detection and run TEST ALL LEAKS.
      Add the leaking DNS server IP as a BYPASS exception rule.
      Most common fix: add the native VPN's DNS server (e.g., 10.64.0.1
      for Mullvad, 103.86.96.100 for NordVPN) as a bypass exception.

  VPN speed dropped after enabling coexistence
    → Check MTU. Run the MTU Optimizer for your mode and apply the result.
      Most common: ip link set ghostnet0 mtu 1420

  Script fails: "RTNETLINK answers: File exists"
    → Rules already exist from a previous run. Run the disable script first,
      then re-run the enable script.

  14. UNINSTALLING
══════════════════════════════════════════════════════════════════════════════

  GhostNet is fully self-contained. Nothing is written to your system
  registry, /usr/local, or any other system location.

  TO UNINSTALL:
  1. Stop GhostNet (close the terminal window or press Ctrl + C).
  2. Delete the GhostNet folder.
  3. Done. No cleanup scripts needed.

  IF YOU SET UP A SYSTEMD SERVICE (Linux):

    sudo systemctl stop ghostnet
    sudo systemctl disable ghostnet
    sudo rm /etc/systemd/system/ghostnet.service
    sudo systemctl daemon-reload
