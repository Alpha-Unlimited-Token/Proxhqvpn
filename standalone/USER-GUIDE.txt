01. DASHBOARD & NODE MANAGER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  The Dashboard is your control center. It shows:
    • Live node count (50 outer + 10 inner = 60 total)
    • Active beacon alerts
    • Trapped attacker count
    • Firewall status
    • Recent intrusion events

  Node Manager (/nodes):
    • 60-node swarm grid with real-time 3s rotation
    • Each node shows: IP, layer (outer/inner), WireGuard port, latency
    • Actions per node:
        - Rotate IP instantly
        - Replace node (new keys + IP)
        - View WireGuard config
    • Bulk actions:
        - Shuffle All IPs (rotate every node simultaneously)
        - Bulk rotate by layer (outer or inner only)

  Node Layers:
    Outer nodes (50):  10.x.x.x range — first hop from user traffic
    Inner nodes (10):  172.16.x.x range — core routing + silk web center

02. BEACON ALERTS & SILK WEB TRAP NETWORK
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Beacon System:
    Every node runs three agents:
      • Beacon — detects unauthorized probes and port scans
      • Spider — crawls attacker traffic patterns
      • Worm — propagates threat signatures across all nodes

  Probe types detected:
    ping, port_scan, traceroute, packet_sniff, tunnel_probe

  Alert severities: critical, high, medium, low

  Silk Web (/silkweb):
    • SVG chord topology map showing all 60 nodes
    • Route types: highway, dead_end, decoy, collapse_zone
    • When an attacker enters the silk web they get looped through
      dead-end routes, wasting their time while you collect data
    • Trapped Entity list — captured attacker IPs + fingerprints
    • Collapse Web — instantly deactivates all routes

03. FIREWALL & BLOCKED IPs
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Firewall Modes: stealth | strict | permissive | lockdown

  Firewall Features:
    • Per-rule direction: inbound, outbound, both
    • Actions: allow, deny, drop, reject, masquerade, log
    • Protocols: TCP, UDP, ICMP, any
    • Source/dest IP + port filtering
    • ISP Masquerade — spoofs ISP-like traffic signatures
    • Localhost Hiding — hides local services from network scans
    • DNS Masking — obfuscates DNS resolver identity
    • IPTables export — download as Linux iptables rules
    • Blocked IPs table — auto-block + manual block with reason tracking

04. WIREGUARD CONFIG GENERATOR
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Route: /wireguard

  Generates ready-to-use WireGuard .conf files for any node in your mesh.

  Config includes:
    [Interface]
      PrivateKey = <node's generated private key>
      Address    = <node's mesh IP>/24
      ListenPort = <node's WireGuard port>
      DNS        = 1.1.1.1, 1.0.0.1

    [Peer]
      PublicKey  = <peer public key>
      AllowedIPs = 0.0.0.0/0, ::/0
      Endpoint   = <node IP>:<port>

  To apply (Linux):
    sudo wg-quick up /path/to/config.conf
  To disconnect:
    sudo wg-quick down /path/to/config.conf

  Device Manager (/devices):
    Register client devices and download per-device configs with QR codes.

05. KILL SWITCH
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Route: /kill-switch

  The Kill Switch blocks ALL internet traffic if the VPN tunnel drops,
  preventing any data from leaking over your real IP.

  Modes:
    • Strict   — block everything except WireGuard interface traffic
    • Permissive — allow local LAN traffic through
    • Auto      — auto-arm when wg0 comes up, auto-disarm when it drops

  OS Script Generator:
    Linux (iptables + ip6tables):
      #!/bin/bash
      iptables -P INPUT DROP
      iptables -P FORWARD DROP
      iptables -P OUTPUT DROP
      iptables -A INPUT -i lo -j ACCEPT
      iptables -A OUTPUT -o lo -j ACCEPT
      iptables -A INPUT -i wg0 -j ACCEPT
      iptables -A OUTPUT -o wg0 -j ACCEPT
      iptables -A OUTPUT -p udp --dport 51820 -j ACCEPT
      # IPv6 mirroring (prevents IPv6 bypass attacks)
      ip6tables -P INPUT DROP
      ip6tables -P FORWARD DROP
      ip6tables -P OUTPUT DROP
      ip6tables -A INPUT -i lo -j ACCEPT
      ip6tables -A OUTPUT -o lo -j ACCEPT
      ip6tables -A INPUT -i wg0 -j ACCEPT
      ip6tables -A OUTPUT -o wg0 -j ACCEPT

    macOS (pf):
      Generated and downloadable from the Kill Switch page.

    Windows (netsh):
      Generated and downloadable from the Kill Switch page.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
06. LEAK DETECTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Route: /leaks

  Tests for three major VPN leak types:

  DNS Leak:
    Verifies your DNS queries go through the VPN, not your ISP.
    Tests: dnsleaktest.com, dnsleak.com, perfect-privacy.com
    Fix: Set DNS = 10.8.0.1 in your WireGuard [Interface]

  IPv6 Leak:
    Checks if your real IPv6 address is exposed.
    Fix: Disable IPv6 system-wide or use the Kill Switch ip6tables rules.

  WebRTC Leak:
    Checks if your browser WebRTC reveals your real IP.
    Fix (Chrome): Install WebRTC Network Limiter extension
    Fix (Firefox): Set media.peerconnection.enabled = false in about:config

  Browser Console Test Script:
    Copy the generated JavaScript snippet into your browser console
    to run a local WebRTC leak check instantly.

07. SPLIT TUNNELING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Route: /split-tunnel

  Route specific traffic through or around the VPN:

  Rule types:
    • By IP     — e.g. 192.168.1.100 bypasses VPN
    • By CIDR   — e.g. 10.0.0.0/8 goes through VPN
    • By port   — e.g. port 80 bypasses VPN
    • By app    — e.g. Firefox goes through VPN, Chrome bypasses

  Actions: route-via-vpn | bypass-vpn | block

  Script Generator:
    Generates Linux ip route commands and Windows netsh rules.

  Example Linux output:
    ip route add 192.168.1.100/32 via <gateway> dev eth0 table bypass
    ip rule add to 192.168.1.100/32 lookup bypass

08. DPI OBFUSCATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Route: /obfuscation

  Bypasses Deep Packet Inspection used by ISPs, firewalls, and censorship.

  Protocols:
    obfs4        — industry standard transport obfuscation (Tor-compatible)
    Shadowsocks  — widely deployed in restrictive regions
    V2Ray-WS     — WebSocket + TLS (appears as normal HTTPS traffic)
    Meek         — routes traffic through cloud CDN (Azure/Google)
    Snowflake    — WebRTC-based (used by Tor Browser in censored regions)
    XOR Cipher   — lightweight packet XOR scrambling

  Config Output:
    Each protocol generates a ready-to-use client config + server config.
    Copy-paste into your obfs4proxy, Shadowsocks, or v2ray binary.

09. ONION BROWSER & PROXY CONFIG
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Route: /onion-browser

  Browse the web through multiple anonymization layers:

    Direct         — standard HTTP/S request (no proxy)
    ProxhqVPN Onion — routes through 7 ProxhqVPN relay nodes
    Tor Gateway    — routes through Tor guard → relay → exit
    Double Layer   — ProxhqVPN relay × 3 → Tor circuit (max anonymity)
    Custom SOCKS4  — your own SOCKS4 proxy
    Custom SOCKS5  — your own SOCKS5 proxy (Tor default: 127.0.0.1:9050)
    Custom HTTP    — your own HTTP proxy

  Port Knocking:
    Sequence-based port access control. Knock ports in sequence before
    connecting to hide your services from port scanners.
    Example knock: 7000, 8000, 9000 → opens SSH port 22 for 30s.

10. DNS SHIELD (AD/MALWARE BLOCKING)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Route: /dns-sinkhole (or /dns-shield)

  Pi-hole / AdGuard-style DNS-level blocking. Toggle categories:
    • Ads         — advertising networks
    • Trackers    — analytics + telemetry
    • Malware     — known malicious domains
    • Phishing    — phishing + credential harvesting sites
    • Cryptomining — browser-based crypto miners
    • Botnet C2   — command-and-control server domains
    • Adult       — adult content (optional)

  Custom Rules:
    Add your own allow rules (whitelist) or block rules (blacklist).
    Supports exact domain match and wildcard (*.example.com).

  Domain Lookup:
    Test any domain instantly to see if it would be blocked or allowed.

  Stats Dashboard:
    • Total queries blocked (24h)
    • Top blocked domains chart
    • Category breakdown
    • Block rate percentage

12. VPN COEXISTENCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Route: /vpn-coexist

  Run ProxhqVPN alongside commercial VPNs simultaneously:
    NordVPN, ExpressVPN, ProtonVPN, Mullvad, Surfshark

  Coexistence modes:
    fwmark         — route by firewall mark (default, zero conflict)
    double-hop     — chain ProxhqVPN → commercial VPN (max privacy)
    namespace      — separate Linux network namespace (total isolation)
    routing-table  — per-table routing (advanced)

  Exception rules:
    bypass-proxhq  — specific IPs skip ProxhqVPN, go through commercial VPN
    force-proxhq   — specific IPs always use ProxhqVPN only
    block          — block specific IPs entirely

  MTU Optimizer:
    Calculates optimal MTU to prevent fragmentation in double-tunnel setups.

  Script Generator:
    Outputs ready-to-run bash/PowerShell setup scripts.

    → PORT=8080 ./ProxhqVPN  (use a different port)

  "permission denied" (macOS)
    → chmod +x ./ProxhqVPN && xattr -d com.apple.quarantine ./ProxhqVPN

  "Node.js not found" (Universal package)
    → Install Node.js 20+ from https://nodejs.org

  Dashboard shows no nodes
    → Delete data/proxhqvpn.db and restart. 60 nodes will be re-seeded.

  WireGuard not working
    → Install: sudo apt install wireguard-tools  (Linux)
               brew install wireguard-tools       (macOS)

  Cannot connect to external PostgreSQL
    → Check firewall allows port 5432. Verify connection string format:
      postgresql://user:pass@host:5432/dbname

  Browser shows "Cannot GET /"
    → Frontend not found. Place the frontend/ folder next to the binary.

  macOS Gatekeeper blocks the app
    → System Preferences → Security → "Open Anyway"
    Or: sudo xattr -r -d com.apple.quarantine ./ProxhqVPN
